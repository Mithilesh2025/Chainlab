02 / BUILDING BLOCKS

Understand the language of backward chaining

Four ideas are enough to read the proof tree. These aren't interchangeable: each has a different job.

◎A / THE QUESTION

Goal

The proposition we want to verify. The search begins here instead of scanning every available fact.

lab_access ?
✓B / STARTING EVIDENCE

Known fact

A statement accepted as true in the knowledge base. A matching fact closes a proof branch.

fees_paid
⇐C / LOGICAL RELATION

Inference rule

An IF–THEN statement: if all its conditions hold, the conclusion can be proven.

lab_access ← verified, fees_paid
▦D / STORED KNOWLEDGE

Knowledge base

The collection of known facts and inference rules that the engine is allowed to use.

Facts + IF–THEN rules
AND

One rule, every condition

To use Lab access IF Verified AND Fees paid, both premises must succeed.

OR

Multiple rules, different paths

If two rules conclude the same goal, proving either complete rule is enough.

04 / HOW IT WORKS

From a goal to a proof

Backward chaining repeatedly finds rules for a goal, creates subgoals, and checks those subgoals until facts resolve the chain—or every alternative fails.

The search procedure

1Ask a questionChoose the desired conclusion.
2Find rules that can establish itEach matching rule offers an OR alternative.
3Check every rule premiseEvery condition is an AND requirement; repeat recursively.
4Prove or backtrackFacts succeed; unsupported branches fail; alternatives are tried.
Important: Not proven means insufficient evidence in this knowledge base—not necessarily that the statement is false.

Pseudocode

RECURSIVE SEARCH
PROCEDURE Prove(goal, path)
  IF goal is a known fact
    RETURN true

  IF goal occurs in path
    RETURN false  // avoid cycles

  FOR EACH rule concluding goal
    IF EVERY premise can be proven
      RETURN true

  RETURN false

Alternative rules use OR. Premises within one rule use AND.

Typical search costCan be exponential

With branching factor b and search depth d, a naive search may take O(bd) time. Actual cost depends on the rule structure.

Recursion memoryO(d) stack depth

For a single search branch, excluding storage for the knowledge base and the visualizer's full history.

Real-world usesDiagnosis and reasoning

Rule-based expert systems, eligibility checks, troubleshooting and logic programming.
